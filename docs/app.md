# Yoru, the desktop app

The desktop app in `app/`: Tauri 2 (`app/src-tauri/`, crate `yoru-app`) around `yoru-core`, with a Svelte 5 UI (`app/src/`). Paths below are under `app/`.

## The UI

- `src/lib/store.svelte.ts`: what the window knows, kept current by the Rust side's events (`bridge`, `inbox`, `chat`, `tasks`, `schedule`, `connectors`, `flash`, `assistant`).
- `src/lib/api.ts`: every command goes through `call()`. Outside Tauri, `src/lib/preview.ts` answers with a mocked Yoru, so `npm run dev` shows every page in a browser (`?setup`, `?board=off`, `?key=none`, `?brain=groq`).
- The window (`src/App.svelte`, since 2026-11-18): a frame holding the page as a rounded card. On the frame, the window bar on top (`src/lib/WindowBar.svelte`), the sidebar on the left (`src/lib/Sidebar.svelte`: Home, Memory, Meetings, with no box of its own) and the activity panel on the right, on every page. The window bar has, over the sidebar and at its right edge (next to the Mac's buttons when the sidebar is folded), the one that folds the sidebar away entirely, and the tabs start where the page's card does (since 2026-11-19); at the right Notifications (a bell with the unread count), Settings (a gear, with a dot when Yoru can't think, a service wants a login or there's an update) and the one that folds the activity panel away entirely. Two themes, light (white pages on a sky-tinted frame) and dark (the board's black), picked in Settings → Appearance: like the Mac (the default), light or dark. The theme and what's folded are kept in `localStorage` (`src/lib/look.svelte.ts`, which sets `html[data-theme]`); the colours are tokens in `src/app.css`, with the light ones under `:root[data-theme="light"]`. The notch never takes the theme: it stays dark. The window uses macOS's own title bar, hidden behind the page (`titleBarStyle: Overlay` in `tauri.conf.json`), so its close, minimize and full-screen buttons are the system's, at the top left over the sidebar, and the corners and shadow are a normal Mac window's; the sidebar's top and the window bar are where it's dragged from. The sidebar has no Yoru of its own (since 2026-11-19): only the pages, and at the bottom the board's state and Do not disturb. It can't be made smaller than 1100×700 (`minWidth`, `minHeight` in `tauri.conf.json`, since 2026-11-19), so no page has to squeeze. Closing it only hides it: Yoru stays in the tray. Tasks, Routines, Services, Spoken and Animations aren't in the sidebar (Tasks and Routines since 2026-11-18): Settings opens them from a plain menu under Yoru's wiring, and they show a way back to Settings. Every icon is Lucide's (`src/lib/icons/lucide.ts`, copied from lucide-static 0.460.0, ISC; `ui/Icon.svelte` draws one), never one drawn by hand; the pages' are in `src/lib/icons/pages.ts`. The type is the Mac's own (SF Pro, `-apple-system`), on one scale of five sizes (`--fs-title`, `--fs-head`, `--fs-body`, `--fs-meta`, `--fs-small` in `src/app.css`, since 2026-11-18); the notch keeps its own sizes. Group names are plain words, not capitals; each page says what it is in one line; a notification shows only Open until you point at it.
- The pages' shared parts (since 2026-11-18, after Pocket's desktop app), all in `src/app.css`, so every page looks the same: one width (`.page`, 880px); a head with the title and one line on the left, the page's buttons on the right (`.page-head .actions`) and a dashed line under it; a group's head with its button (`.section-head`); lists as open rows with dashed lines between them and a soft grey under the one pointed at, never a card per item (`.list`, with `.item-head`, `.item-text`, `.item-meta`, `.item-actions`); settings as one card of rows, dashed lines between them (`.panel` of `.setting`); views of one thing as a segmented pill (`.seg`); filters and choices as outlined pills, the one picked solid (`.chips`, `.chip`); buttons as pills on the field colour, the main one solid, a dangerous one soft red. Fields are white with a thin border in the light theme; switches are green. Borders are as faint as Pocket's (`--rim`, `--rim-2`, since 2026-11-19) and a pointed-at or picked row is a soft grey (`--hover`). Every repeated part is a class there, never a page's own copy (since 2026-11-19): icon buttons (`.icon-btn`, with `.small`, `.round`, `.filled`, `.outline`, `.primary`), counts on them (`.count`), the sidebar's and the activity panel's rows (`.nav-row`), a link-looking button (`.btn.link`), fields (`select` sized to its options; `.compact`, `.bare` for a name typed in place), a card picked (`.panel.active`), a form on its own (`.panel.raised`), a sunken box for logs and details (`.well`), a choice card (`.tile.inset`), a bar that fills (`.meter`, `--p`), small and tinted pills (`.chip.small`, `.chip.tint`), tags (`.tag.think`, `.tag.done`, `.tag.outline`), and the dialogs' backdrop and sheet (`.veil`, `.sheet`).
- Home (`src/lib/pages/Home.svelte`; since 2026-11-19 after Pocket's home): every conversation with Yoru and every meeting recorded, newest first, by day (Today, Yesterday, then the weekday and date), each a row with its kind (a round bubble for a chat, a sheet for a meeting), its title (a chat Yoru hasn't named shows its first words, faint) and the time; the one Yoru is in says "in corso". Pointing at a row shows a bin in place of the time. A search over titles and first words (⌘K), Record (to Meetings) and New conversation at the top, the confirmations waiting above the list, and at the bottom the field to ask Yoru something, which starts a new conversation in its own tab. With nothing yet, Yoru greets you in the middle with a few suggestions.
- Tabs (`src/lib/tabs.svelte.ts` and `WindowBar.svelte`, since 2026-11-19, as in Pocket): the window bar's first tab is the page the sidebar picks; after it, the conversations and meetings opened, each a tab of its own with a × (a middle click closes it too), and + for a new conversation, all lined up from the left. They're kept in `localStorage` (12 at most), so the window opens on what was open; a conversation or meeting deleted closes its tab.
- A conversation's tab (`src/lib/pages/Chat.svelte`): with nothing said, Yoru as a mascot in the middle with a short greeting and a few suggestions; then Yoru small at the left of the newest line (his answer, your question or his thinking dots), moving down with it. He's his own, not the board's mirror (awake with no board on the desk), white and without a shadow (since 2026-11-19), and his eyes follow the pointer while it's in the window (`follow` on `YoruBoard.svelte`). Above it, the conversation's title: Yoru names it after his first answer and again each time the conversation has doubled, with the brain in use, in the reply language; click it to rename it (Enter keeps it, Escape leaves it, an empty one gives it back to Yoru, who then leaves a typed one alone). Next to it a bin, which asks before deleting the conversation. The conversation (`ui/ChatLog.svelte`: the tools folded under each answer, the words being said, the thinking dots, the cards waiting, in the body text size), and at the bottom the field to type, with a microphone button (`ui/Composer.svelte` with `mic`; `conversation` says which conversation it writes in, `"new"` for a new one): click to talk, click again to send what you said, and while he answers aloud it stops him. Only the conversation Yoru is in is live; an earlier one shows as it was, and writing in it takes it up again (it becomes the one he's in). It talks through the Mac's ears and voice, the notch's session (`notch_talk`, `notch_hush`), which runs whether or not the notch is shown; its `notch` events reach every window, and the store keeps them (`macVoice`, `macLevel`, `macReaction`). The mascot thinks while an answer is on its way, listens and talks with the Mac's voice or the board's, plays the reactions Yoru plays, and reacts to each new line of the chat (`src/lib/mood.ts`: a thank you gets love, an apology shyness, an error sadness, a question curiosity, a greeting a wave, in English and Italian).
- Yoru at the bottom right of every page but the Home and a conversation's tab (`src/lib/YoruBubble.svelte`, `src/lib/bubble.svelte.ts`, since 2026-11-19): the mascot, awake like the chat's (eyes on the pointer, thinking, reactions, a dot when a confirmation waits). A click opens his chat over the page, on the conversation he's in, with + for a new one, a button that moves it into a tab of its own, and × (or Escape). A page can open it with words already in the field (`bubble.show(draft)`; `Composer`'s `text` is bindable for this), as the Memory page's "Tell Yoru" does.
- A meeting's tab (`src/lib/pages/MeetingView.svelte`, since 2026-11-19): its title, date and length, the two tracks to listen to, and Summary and Transcript as a segmented pill (the summary first when there is one): summarize or summarize again, copy it; the transcript with its exports, transcribe again, the speakers to name, a click on a line plays it. The Meetings page lists the recordings and opens each in its tab. On the right of every page, on the frame and only as tall as what it lists, the activity panel (`ui/ActivityPanel.svelte`), which the window bar's button folds away entirely: the coding agents at work, the tasks (running, next run or last run) and the routines (the morning recap and the watchers on, with their last run). A line opens its detail in a dialog in the middle of the window (`ui/Dialog.svelte`), with Do it now or Stop and a way to its page.
- `src/lib/pages/`: Home, Inbox, Connectors, Tasks (the jobs you give Yoru, with `ui/TaskEditor.svelte`), Routines (the recap, quiet hours, watchers), Memory (the graph, `ui/MemoryGraph.svelte`, filling the page; a click on a node opens its card, where everything is changed, or tell Yoru), Meetings (recordings, `docs/meetings.md`), Spoken (what a cloud voice said, a tab per source: ElevenLabs a sentence at a time, Gemini Live an answer at a time, never mixed; clearing and exporting work on one source), Animations (every animation clip the board has, to play on it one at a time or all in a row, mirrored or in a service's colours; through the board's `debug/clips` and `debug/clip`), Settings. Settings opens on Yoru wired to seven cards (since 2026-11-13): on the left what Yoru is (how he thinks and talks, voice, language), on the right what he's connected to (keys, on the Mac, the board, about). Under the wiring, "Also here" lists Tasks, Routines, Services, Spoken and Animations, which aren't wired to him. The cards are in a grid, never placed by hand (since 2026-11-19): with room, a column each side of Yoru, the cards stacked in it and the wires drawn to where they really are (measured, so a card that grows can't cover another); in a narrower window Yoru on top and the cards in two columns under him, without wires. The first card opens on four setups (since 2026-11-17, `src/lib/profiles.ts` and `ui/Profiles.svelte`): Free (Groq thinks and transcribes, this Mac speaks), The best (Claude, this Mac transcribes, ElevenLabs speaks when its key is there), Live (Gemini Live, with Gemini for typing) and Private (Ollama and this Mac). One click sets the brain and the voice together; under the one in use only what it still needs (its key, the Ollama model, Live's voice), and "Test Yoru" checks the brain, hearing and voice in order, then has him say a sentence, naming the first thing that fails in plain words. Changing a part by hand makes the setup "Custom": under "Customize" the brain and its model (Claude's by name: Opus, Sonnet, Haiku) and, for Claude only, the thinking effort and web search. Gemini Live is a setup, not a voice option: the voice page only says when it's on, with a button to turn it off, and folds the transcription, end-of-turn and goodbye models under "Advanced". Every API key is on the keys page too. The first run (`src/lib/Setup.svelte`) offers the same setups. On the Mac holds the notch and Yoru's MCP server in Claude Code; the board's page keeps only the hardware (firmware, WiFi, the board's own settings).
- The first run (`src/lib/Setup.svelte`, since 2026-11-18) has six steps: the language; the Mac's permissions (`ui/PermissionList.svelte`) with Yoru in the notch and noticing meetings (both on by default); the board; the setup; a first service; a few lines about you. The microphone is required: Next and Skip wait for it. The calendar and the system audio are for meetings and can be left for later. After the first run, `src/lib/PermissionGate.svelte` covers the window whenever the microphone isn't Yoru's (turned off in System Settings, a new Mac), and goes away by itself once it is: the list reads the permissions again every second. Settings → On the Mac lists them too, with Allow for one never asked (macOS adds Yoru to System Settings' list only once it has asked), Ask again for one turned down, and Change, which opens System Settings at it, to turn one off.
- `src/lib/updates.ts` and `bundled.ts`: the firmware the app carries and what flashing it changes, from `firmware/yoru/`.
- `src/Notch.svelte`: Yoru in the Mac's notch, the same bundle mounted in the notch's window (`window.__YORU_NOTCH__`, or `?notch` in the browser preview) ([notch.md](notch.md)).
- `src/lib/i18n/`: `en.ts` and `it.ts`, key for key (`npm run check` fails on a missing one).

## The Rust side

- `src-tauri/src/lib.rs`: the bridge to the board, voice, firmware, WiFi, the board's animation clips (`yoru_clips`, `yoru_play_clip`, `yoru_stop_clip`: raw JSON-RPC test hooks, not MCP tools), the MCP server's entry in Claude Code's config, timers, the tray.
- `src-tauri/src/notch.rs`: the notch's window above the menu bar, the pointer that lets clicks through, and the ⌥ Space push-to-talk key ([notch.md](notch.md)).
- `src-tauri/src/assistant.rs`: the assistant's commands (ask, inbox, tasks, memory, watchers, recap, connectors) and the scheduler and connectors started with the app.
- `src-tauri/src/meetings.rs`: the meetings' commands (sources, start, stop, the recordings, import, transcripts one at a time, exports, the meetings' settings, the model's download) and the `meeting` event. The recording runs in `yoru-audio`, the Swift helper in `../audio/`, which `src-tauri/build.rs` builds into `src-tauri/binaries/` on every macOS build (it needs Xcode or its command line tools); `src-tauri/Info.plist` says why macOS asks for the microphone, the system audio, the calendar and the local network.
- `src-tauri/src/permissions.rs`: the Mac's permissions, read and asked by the app's own process (`permissions`, `request_permission`, `open_privacy`): the microphone with AVFoundation, the calendar with EventKit, the system audio with the TCC framework's own calls (looked up at run time; there's no public one). They used to be asked by `yoru-audio`, and macOS showed no prompt for a helper process, so the notch's "Allow" did nothing. A permission turned down, or one macOS neither grants nor asks about (a record left by an older build), is forgotten with `tccutil reset <service> it.bytebusters.yoru.hub` and asked again, so the button always brings macOS's prompt back: sending the user to System Settings instead led to a list Yoru wasn't on (an app shows up there only once a prompt was answered). System Settings opens only for a permission a profile holds, or one turned down again. The system audio reads as unsupported before macOS 14.2, where TCC doesn't know the service and says denied. The permissions at launch, the macOS version and each request are written in `yoru.log` (`[permissions]`).

## Commands

In `app/`:

```bash
npm run dev           # the UI in a browser, mocked
npm run tauri dev     # the real app
npm run check         # svelte-check
npm run build         # the UI bundle
```
