# Yoru, the desktop app

The desktop app in `app/`: Tauri 2 (`app/src-tauri/`, crate `yoru-app`) around `yoru-core`, with a Svelte 5 UI (`app/src/`). Paths below are under `app/`.

## The UI

- `src/lib/store.svelte.ts`: what the window knows, kept current by the Rust side's events (`bridge`, `inbox`, `chat`, `tasks`, `schedule`, `connectors`, `flash`, `assistant`).
- `src/lib/api.ts`: every command goes through `call()`. Outside Tauri, `src/lib/preview.ts` answers with a mocked Yoru, so `npm run dev` shows every page in a browser (`?setup`, `?board=off`, `?key=none`, `?brain=groq`).
- The window (`src/App.svelte`, since 2026-11-18): a frame holding the page as a rounded card. On the frame, the window bar on top (`src/lib/WindowBar.svelte`), the sidebar on the left (`src/lib/Sidebar.svelte`: Home, Tasks, Routines, Memory, Meetings, with no box of its own) and, on the Home, the activity panel on the right. The window bar has, next to the Mac's buttons, the one that folds the sidebar away entirely; at the right Notifications (a bell with the unread count), Settings (a gear, with a dot when Yoru can't think, a service wants a login or there's an update) and, on the Home, the one that folds the activity panel away entirely. Two themes, light (white pages on a sky-tinted frame) and dark (the board's black), picked in Settings → Appearance: like the Mac (the default), light or dark. The theme and what's folded are kept in `localStorage` (`src/lib/look.svelte.ts`, which sets `html[data-theme]`); the colours are tokens in `src/app.css`, with the light ones under `:root[data-theme="light"]`. The notch never takes the theme: it stays dark. The window uses macOS's own title bar, hidden behind the page (`titleBarStyle: Overlay` in `tauri.conf.json`), so its close, minimize and full-screen buttons are the system's, at the top left over the sidebar, and the corners and shadow are a normal Mac window's; the sidebar's header and the window bar are where it's dragged from. Closing it only hides it: Yoru stays in the tray. Services, Spoken and Animations aren't in the sidebar: Settings opens them from a plain menu under Yoru's wiring, and they show a way back to Settings. The pages' icons are in `src/lib/icons/pages.ts`. The main window's page is zoomed to 108% (`MAIN_ZOOM` in `src-tauri/src/lib.rs`), so every text is a little larger; the notch keeps its size.
- Home (`src/lib/pages/Home.svelte`, since 2026-11-18; it replaced Today and Conversation): Yoru as a mascot at the top, his own and not the board's mirror (awake with no board on the desk), then the conversation (`ui/ChatLog.svelte`: the tools folded under each answer, the words being said, the thinking dots, the cards waiting), and at the bottom the field to type, with a microphone button (`ui/Composer.svelte` with `mic`): click to talk, click again to send what you said, and while he answers aloud it stops him. It talks through the Mac's ears and voice, the notch's session (`notch_talk`, `notch_hush`), which runs whether or not the notch is shown; its `notch` events reach every window, and the store keeps them (`macVoice`, `macLevel`, `macReaction`). The mascot thinks while an answer is on its way, listens and talks with the Mac's voice or the board's, plays the reactions Yoru plays, and reacts to each new line of the chat (`src/lib/mood.ts`: a thank you gets love, an apology shyness, an error sadness, a question curiosity, a greeting a wave, in English and Italian). On the right, on the frame and only as tall as what it lists, the activity panel (`ui/ActivityPanel.svelte`), which the window bar's button folds away entirely: the coding agents at work, the tasks (running, next run or last run) and the routines (the morning recap and the watchers on, with their last run). A line opens its detail in a dialog in the middle of the window (`ui/Dialog.svelte`), with Do it now or Stop and a way to its page.
- `src/lib/pages/`: Home, Inbox, Connectors, Tasks (the jobs you give Yoru, with `ui/TaskEditor.svelte`), Routines (the recap, quiet hours, watchers), Memory (a graph, `ui/MemoryGraph.svelte`, or a list), Meetings (recordings, `docs/meetings.md`), Spoken (what a cloud voice said, a tab per source: ElevenLabs a sentence at a time, Gemini Live an answer at a time, never mixed; clearing and exporting work on one source), Animations (every animation clip the board has, to play on it one at a time or all in a row, mirrored or in a service's colours; through the board's `debug/clips` and `debug/clip`), Settings. Settings opens on Yoru wired to seven cards (since 2026-11-13): on the left what Yoru is (how he thinks and talks, voice, language), on the right what he's connected to (keys, on the Mac, the board, about). Under the wiring, "Also here" lists Services, Spoken and Animations, which aren't wired to him. Each side's cards are spread evenly around the middle, so the three on the left sit centred against the four on the right. The first card opens on four setups (since 2026-11-17, `src/lib/profiles.ts` and `ui/Profiles.svelte`): Free (Groq thinks and transcribes, this Mac speaks), The best (Claude, this Mac transcribes, ElevenLabs speaks when its key is there), Live (Gemini Live, with Gemini for typing) and Private (Ollama and this Mac). One click sets the brain and the voice together; under the one in use only what it still needs (its key, the Ollama model, Live's voice), and "Test Yoru" checks the brain, hearing and voice in order, then has him say a sentence, naming the first thing that fails in plain words. Changing a part by hand makes the setup "Custom": under "Customize" the brain and its model (Claude's by name: Opus, Sonnet, Haiku) and, for Claude only, the thinking effort and web search. Gemini Live is a setup, not a voice option: the voice page only says when it's on, with a button to turn it off, and folds the transcription, end-of-turn and goodbye models under "Advanced". Every API key is on the keys page too. The first run (`src/lib/Setup.svelte`) offers the same setups. On the Mac holds the notch and Yoru's MCP server in Claude Code; the board's page keeps only the hardware (firmware, WiFi, the board's own settings).
- The first run (`src/lib/Setup.svelte`, since 2026-11-18) has six steps: the language; the Mac's permissions (`ui/PermissionList.svelte`) with Yoru in the notch and noticing meetings (both on by default); the board; the setup; a first service; a few lines about you. The microphone is required: Next and Skip wait for it. The calendar and the system audio are for meetings and can be left for later. After the first run, `src/lib/PermissionGate.svelte` covers the window whenever the microphone isn't Yoru's (turned off in System Settings, a new Mac), and goes away by itself once it is: the list reads the permissions again every second. Settings → On the Mac lists them too, with Allow for one never asked (macOS adds Yoru to System Settings' list only once it has asked), Ask again for one turned down, and Change, which opens System Settings at it, to turn one off.
- `src/lib/updates.ts` and `bundled.ts`: the firmware the app carries and what flashing it changes, from `firmware/yoru/`.
- `src/Notch.svelte`: Yoru in the Mac's notch, the same bundle mounted in the notch's window (`window.__YORU_NOTCH__`, or `?notch` in the browser preview) ([notch.md](notch.md)).
- `src/lib/i18n/`: `en.ts` and `it.ts`, key for key (`npm run check` fails on a missing one).

## The Rust side

- `src-tauri/src/lib.rs`: the bridge to the board, voice, firmware, WiFi, the board's animation clips (`yoru_clips`, `yoru_play_clip`, `yoru_stop_clip`: raw JSON-RPC test hooks, not MCP tools), the MCP server's entry in Claude Code's config, timers, the tray.
- `src-tauri/src/notch.rs`: the notch's window above the menu bar, the pointer that lets clicks through, and the ⌥ Space push-to-talk key ([notch.md](notch.md)).
- `src-tauri/src/assistant.rs`: the assistant's commands (ask, inbox, tasks, memory, watchers, recap, connectors) and the scheduler and connectors started with the app.
- `src-tauri/src/meetings.rs`: the meetings' commands (sources, start, stop, the recordings, import, transcripts one at a time, exports, the meetings' settings, the model's download) and the `meeting` event. The recording runs in `yoru-audio`, the Swift helper in `../audio/`, which `src-tauri/build.rs` builds into `src-tauri/binaries/` on every macOS build (it needs Xcode or its command line tools); `src-tauri/Info.plist` says why macOS asks for the microphone, the system audio, the calendar and the local network.
- `src-tauri/src/permissions.rs`: the Mac's permissions, read and asked by the app's own process (`permissions`, `request_permission`, `open_privacy`): the microphone with AVFoundation, the calendar with EventKit, the system audio with the TCC framework's own calls (looked up at run time; there's no public one). They used to be asked by `yoru-audio`, and macOS showed no prompt for a helper process, so the notch's "Allow" did nothing. A permission turned down, or one macOS neither grants nor asks about (a record left by an older build), is forgotten with `tccutil reset <service> it.bytebusters.yoru.hub` and asked again, so the button always brings macOS's prompt back: sending the user to System Settings instead led to a list Yoru wasn't on (an app shows up there only once a prompt was answered). System Settings opens only for a permission a profile holds, or one turned down again. The system audio reads as unsupported before macOS 14.2, where TCC doesn't know the service and says denied. The permissions at launch, the macOS version and each request are written in `yoru.log` (`[permissions]`).

## Commands

In `app/`:

```bash
npm run dev           # the UI in a browser, mocked
npm run tauri dev     # the real app
npm run check         # svelte-check
npm run build         # the UI bundle
```
