# Yoru, the desktop app

The desktop app in `app/`: Tauri 2 (`app/src-tauri/`, crate `yoru-app`) around `yoru-core`, with a Svelte 5 UI (`app/src/`). Paths below are under `app/`.

## The UI

- `src/lib/store.svelte.ts`: what the window knows, kept current by the Rust side's events (`bridge`, `inbox`, `chat`, `tasks`, `schedule`, `connectors`, `flash`, `assistant`).
- `src/lib/api.ts`: every command goes through `call()`. Outside Tauri, `src/lib/preview.ts` answers with a mocked Yoru, so `npm run dev` shows every page in a browser (`?setup`, `?board=off`, `?key=none`, `?brain=groq`).
- The window (`src/App.svelte`, since 2026-11-18): a frame holding the page as a rounded card. On the frame, the window bar on top (`src/lib/WindowBar.svelte`), the sidebar on the left (`src/lib/Sidebar.svelte`: Home, Scheduled ("Pianificate", back in the sidebar since 2026-11-25), Memory, Meetings, To-do with the count of open to-dos, with no box of its own) and the activity panel on the right, on every page but Meetings, where the right side is the meeting picked on its calendar (docs/meetings.md). The window bar has, over the sidebar and at its right edge (next to the Mac's buttons when the sidebar is folded), the one that folds the sidebar away entirely, and the tabs start where the page's card does (since 2026-11-19); at the right Record (since 2026-11-20, as in Pocket: a white pill with a red dot that starts recording what the Meetings page has picked (New meeting → Sources and microphones), everything played and the default microphones until you pick; while recording it's Stop with the time, the dot blinking; a failure opens Meetings, where it's shown), Notifications (a bell with the unread count), Settings (a gear, with a dot when Yoru can't think, a service wants a login or there's an update) and the one that folds the activity panel away entirely. Two themes, light (white pages on a sky-tinted frame) and dark (the board's black), picked in Settings → General → Theme: like the Mac (the default), light or dark. The theme and what's folded are kept in `localStorage` (`src/lib/look.svelte.ts`, which sets `html[data-theme]`); the colours are tokens in `src/app.css`, with the light ones under `:root[data-theme="light"]`. The notch never takes the theme: it stays dark. The window uses macOS's own title bar, hidden behind the page (`titleBarStyle: Overlay` in `tauri.conf.json`), so its close, minimize and full-screen buttons are the system's, at the top left over the sidebar, and the corners and shadow are a normal Mac window's; the sidebar's top and the window bar are where it's dragged from. The sidebar has no Yoru of its own (since 2026-11-19): only the pages, and at the bottom iCloud sync while it is on (since 2026-11-25: a dot, when it last sent or received records, or Starting, Error or No account, and a cloud; a click opens Settings → iCloud), the Pocket recorder while it is on (since 2026-11-19; since 2026-11-20 a row like the board's, a dot on the left, its name, Connected or Not connected and the Bluetooth icon; a click opens its dialog, `ui/PocketDialog.svelte`, with its storage, firmware, the recordings and Sync, or the pairing steps), the board (a dot, Yoru, Connected or Not connected, and the USB or WiFi icon) and Do not disturb. It can't be made smaller than 1100×700 (`minWidth`, `minHeight` in `tauri.conf.json`, since 2026-11-19), so no page has to squeeze. Closing it only hides it: Yoru stays in the tray. Services, Spoken and Animations aren't in the sidebar: Settings opens them from its rows (Services under Accounts and services, Spoken from Intelligence, Animations from the board's page), and they show a way back to Settings. Animations (since 2026-11-21) shows each clip as a card with a preview drawn in the app as the board draws it (`lib/clips.ts`, `ui/ClipPreview.svelte`, from the bundled firmware's `firmware/yoru/clips.json`): still on its most telling frame, it plays while the pointer is on it, mirrored or in a service's colours as picked; its button plays it on the board. With no board the bundled clips still show, as previews only. Every icon is Untitled UI's (`src/lib/icons/icons.ts`, copied from @untitledui/icons 0.0.23, since 2026-11-20; the set Pocket draws with; `ui/Icon.svelte` draws one), never one drawn by hand. Untitled UI's licence allows them in an app but not handing them on as an icon set, so only the ones the app uses are copied in, and the set is not published on its own. It has no brain, plug or USB cable, so Memory is a light bulb, Services a puzzle piece and USB a flash drive. Where you are shows filled (since 2026-11-20): the sidebar's page, and the bell and the gear while Notifications or Settings is open; the free set has no filled icons, so those few are made from the same lines (`FILLED` in `icons.ts`, the cut-outs a mask so they show what's behind); the pages' are in `src/lib/icons/pages.ts`. The type is the Mac's own (SF Pro, `-apple-system`), on one scale of five sizes (`--fs-title`, `--fs-head`, `--fs-body`, `--fs-meta`, `--fs-small` in `src/app.css`, since 2026-11-18); the notch keeps its own sizes. Group names are plain words, not capitals; each page says what it is in one line; a notification shows only Open until you point at it.
- The pages' shared parts (since 2026-11-18, after Pocket's desktop app), all in `src/app.css`, so every page looks the same: one width (`.page`, 880px); a head with the title and one line on the left, the page's buttons on the right (`.page-head .actions`) and a dashed line under it; a group's head with its button (`.section-head`); lists as open rows with dashed lines between them and a soft grey under the one pointed at, never a card per item (`.list`, with `.item-head`, `.item-text`, `.item-meta`, `.item-actions`); settings as one card of rows, dashed lines between them (`.panel` of `.setting`); views of one thing as a segmented pill (`.seg`); filters and choices as outlined pills, the one picked solid (`.chips`, `.chip`); buttons as pills on the field colour, the main one solid, a dangerous one soft red. Fields are white with a thin border in the light theme; switches are green. Borders are as faint as Pocket's (`--rim`, `--rim-2`, since 2026-11-19) and a pointed-at or picked row is a soft grey (`--hover`). Every repeated part is a class there, never a page's own copy (since 2026-11-19): icon buttons (`.icon-btn`, with `.small`, `.round`, `.filled`, `.outline`, `.primary`), counts on them (`.count`), the sidebar's and the activity panel's rows (`.nav-row`), a link-looking button (`.btn.link`), fields (`select` sized to its options; `.compact`, `.bare` for a name typed in place), a card picked (`.panel.active`), a form on its own (`.panel.raised`), a sunken box for logs and details (`.well`), a choice card (`.tile.inset`), a bar that fills (`.meter`, `--p`), small and tinted pills (`.chip.small`, `.chip.tint`), tags (`.tag.think`, `.tag.done`, `.tag.outline`), and the dialogs' backdrop and sheet (`.veil`, `.sheet`).
- Home (`src/lib/pages/Home.svelte`; since 2026-11-19 after Pocket's home): every conversation with Yoru and every meeting recorded, newest first, by day (Today, Yesterday, then the weekday and date), each a row with its kind (a round bubble for a chat, a sheet for a meeting), its title (a chat Yoru hasn't named shows its first words, faint) and the time; the one Yoru is in says "in corso". Pointing at a row shows a bin in place of the time. A search over titles and first words (⌘K), New conversation at the top (Record moved to the window bar on 2026-11-20), the confirmations waiting above the list, and at the bottom the field to ask Yoru something, which starts a new conversation in its own tab. With nothing yet, Yoru greets you in the middle with a few suggestions. While the Pocket syncs (since 2026-11-24), the recordings it is copying head the list under From the Pocket: the one under way with a bar and its percentage, the others waiting their turn; a click opens the Pocket's dialog.
- Folders (since 2026-11-25): the user's own groups of conversations and meetings. The sidebar lists them under the pages, under Folders, each with how many items it holds; the button next to the heading names a new one in place (Enter saves, Esc cancels). A click on a folder shows only its items on Home, with its name as the title, a pencil to rename it in place and a bin to delete it (asking first); Home in the sidebar shows everything again, where a row in a folder carries the folder's name. A row goes in a folder dragged onto it in the sidebar, or from the folder button that shows next to the bin when pointing at the row (a menu of the folders, and No folder to take it out). An item is in one folder or none; deleting a folder never deletes what's in it, which goes back to no folder; a new conversation started inside a folder goes in it. Kept apart from the items, in `folders.json` in the data folder (`core/src/assistant/folders.rs`, commands in `src-tauri/src/folders.rs`): the folders (id, name, order, `updated`) and each item's place (`chat` or `meeting`, its id, the folder, `updated`), so a move never rewrites a conversation or a meeting. Shaped for iCloud sync (`docs/icloud.md`): one record per folder and one per place, last writer wins per record; a deleted folder stays as a tombstone (`deleted`) and an item taken out keeps its place with no folder, for 30 days, and a place naming a folder that's gone counts as no folder. The icons are Untitled UI's Folder and FolderPlus.
- Tabs (`src/lib/tabs.svelte.ts` and `WindowBar.svelte`, since 2026-11-19, as in Pocket): the window bar's first tab is the page the sidebar picks; after it, the conversations and meetings opened, each a tab of its own with a × (a middle click closes it too), and + for a new conversation, all lined up from the left. They're kept in `localStorage` (12 at most), so the window opens on what was open; a conversation or meeting deleted closes its tab.
- A conversation's tab (`src/lib/pages/Chat.svelte`): with nothing said, Yoru as a mascot in the middle with a short greeting, the model he answers with (to pick it before the first message) and a few suggestions; then Yoru small at the left of the newest line (his answer, your question or his thinking dots), moving down with it. He's his own, not the board's mirror (awake with no board on the desk), white and without a shadow (since 2026-11-19), and his eyes follow the pointer while it's in the window (`follow` on `YoruBoard.svelte`). Above it, the conversation's title: Yoru names it after his first answer and again each time the conversation has doubled, with the brain in use, in the reply language; click it to rename it (Enter keeps it, Escape leaves it, an empty one gives it back to Yoru, who then leaves a typed one alone). On its right (since 2026-11-21) the model Yoru answers with (`ui/ChatModel.svelte`, the compact `ModelPicker`): every service with a key and Ollama's models, the described ones first; picking one sets the brain and its model in the settings, as Settings → Intelligence does, and a new brain starts its messages afresh, reminded of the conversation's last lines. Then how full the context is (`ui/ContextMeter.svelte`, `context_use`, read after each line): a ring with the share of the model's window (Claude's from the Models API; the others' isn't known, so it shows the tokens), and on a click the split of the last request into Yoru's instructions, the notes, the tools, the conversation and the tools' results, with what is free (`core/src/assistant/context.rs`). The total is the provider's count (Claude's `usage`, the others' `prompt_tokens` on a typed question); the split follows each part's size; without a count (a spoken turn on OpenAI, Gemini or Groq, any Ollama turn) it is an estimate and says so. Next to it a bin, which asks before deleting the conversation. The conversation (`ui/ChatLog.svelte`: the tools folded under each answer, the words being said, the thinking dots, the cards waiting, in the body text size), and at the bottom the field to type, with a microphone button (`ui/Composer.svelte` with `mic`; `conversation` says which conversation it writes in, `"new"` for a new one): click to talk, click again to send what you said, and while he answers aloud it stops him. Only the conversation Yoru is in is live; an earlier one shows as it was, and writing in it takes it up again (it becomes the one he's in). It talks through the Mac's ears and voice, the notch's session (`notch_talk`, `notch_hush`), which runs whether or not the notch is shown; its `notch` events reach every window, and the store keeps them (`macVoice`, `macLevel`, `macReaction`). The mascot thinks while an answer is on its way, listens and talks with the Mac's voice or the board's, plays the reactions Yoru plays, and reacts to each new line of the chat (`src/lib/mood.ts`: a thank you gets love, an apology shyness, an error sadness, a question curiosity, a greeting a wave, in English and Italian).
- Yoru's answers are Markdown (`ui/Markdown.svelte`, `src/lib/markdown.ts`, since 2026-11-24), in the conversation, the bubble and the notch: headings, lists, bold and italic, inline code and code blocks, tables, quotes, and ```mermaid blocks drawn as diagrams. `marked` parses, DOMPurify cleans (answers can carry text from web pages and connectors): raw HTML shows as text, images become links (nothing is fetched), only http, https and mailto links are kept, and a click opens them in the browser (`open_web`). Mermaid is loaded the first time a diagram is shown (`securityLevel: strict`), in the window's theme (the notch's is always dark); a diagram it can't read stays as its code. A fence still open while the answer is written is closed for the moment, and an open mermaid one shows as code until it ends. The preview (`src/lib/preview.ts`) has such an answer in the chat, and asking it for "markdown" or a "diagram" writes it a piece at a time.
- Yoru at the bottom right of every page but the Home and a conversation's tab (`src/lib/YoruBubble.svelte`, `src/lib/bubble.svelte.ts`, since 2026-11-19): the mascot, awake like the chat's (eyes on the pointer, thinking, reactions, a dot when a confirmation waits). A click opens his chat over the page as a speech bubble whose tail points at him (lifted off the page by a lighter card, a rim and a shadow, and kept inside the page's card however narrow the window, since 2026-11-20), on the conversation he's in, with + for a new one, a button that moves it into a tab of its own, and × (or Escape). A page can open it with words already in the field (`bubble.show(draft)`; `Composer`'s `text` is bindable for this), as the Memory card's "Tell Yoru about" does.
- A meeting's tab (`src/lib/pages/MeetingView.svelte`, since 2026-11-19): its title, date and length, the two tracks to listen to, and Transcript and Summary as a segmented pill, in that order since 2026-11-24 since a summary is written from the transcript (the summary shown first when there is one; without a transcript the Summary view says it needs one, or that it comes once the transcript in progress is ready, with a button to the Transcript): summarize or summarize again, copy it; the transcript with its exports, transcribe again, the speakers to name, a click on a line plays it. Transcription readiness follows the selected local or online engine, with a visible reason and a link to Meetings settings when a prerequisite is missing. Home lists the meetings and opens each in its tab; the Meetings page (since 2026-11-25) is a calendar of the week or the day with the Mac calendar's meetings and the recordings on it, the picked one in the panel on the right, New meeting (record now, bring in a file, the Pocket, the sources) and Past, and a field at the bottom to ask Yoru about them (docs/meetings.md). On the right of every page, on the frame and only as tall as what it lists, the activity panel (`ui/ActivityPanel.svelte`), which the window bar's button folds away entirely: the coding agents at work, the scheduled tasks (running, next run or last run; the morning recap is one of them) and the watchers on, with their last run. A line opens its detail in a dialog in the middle of the window (`ui/Dialog.svelte`), with Do it now or Stop and a way to its page.
- `src/lib/pages/`: Home, Inbox, Connectors, Tasks (shown as Scheduled, "Pianificate": since 2026-11-25 it holds the scheduled tasks, the watchers and what the scheduler did lately; there are no routines any more), Memory, Meetings, To-do, Spoken, Animations and Settings. To-do (`pages/Todos.svelte`, since 2026-11-20) lists every summarized meeting's things to do, grouped by meeting (its name opens the meeting's tab), with Open, Done and All, a search, a round tick for each, the owner, the day (late ones in red), the kind and a message's or email's draft to copy; the store keeps them (`store.todos`, `meeting_todos`, `set_meeting_todo`) and asks again when a summary is written. Settings (redone on 2026-11-20 for people who aren't technical) is sorted by what you want done, not by how Yoru is built, and every setting lives in one place only. There is no status card on top (removed on 2026-11-24): a row shows a dot when something there is wrong (no brain or no key, a brain's limit), the board's row an update and Services a login. There are no quick settings (removed on 2026-11-24: each repeated a setting kept elsewhere). Then rows in groups: Yoru (Intelligence), Devices (Yoru board, Pocket, This Mac), Accounts and services (Services, and iCloud since 2026-11-25: sync between Macs, `ui/ICloudSettings.svelte`, docs/icloud.md), and General (the theme, the app's language, the quiet hours (since 2026-11-25, when they left the routines), Show advanced options, run the first setup again, and with advanced options the data folder). A row opens its page, with a way back. Show advanced options (`look.advanced`, kept in `localStorage`) is one switch for every page: it shows the models that judge a voice turn (at the bottom of Intelligence's Listens), the board's transport, port and logs, and the MCP command; without it each page keeps only the everyday choices. Intelligence (`ui/Intelligence.svelte`, since 2026-11-24; the part's id is still `brain`) holds every model and key, and since 2026-11-24 the settings of each job too, so there is no separate Voice and listening or Meetings page: one row per job, in three groups, When you talk to Yoru (Listens, Thinks and answers, Speaks), Meetings (Transcribes, Summarizes) and Always (Remembers, Searches the web, Keys), with no presets. A closed row says who does the job (the service's logo and the model) and whether its data stays on this Mac (a green laptop) or goes online (a blue wifi sign); Thinks and answers shows Choose… with no brain yet, and a brain's limit in orange. One row is open at a time: who does it, as service pills (a key sign on those without a key), a line on the service, then its models as a list with Recommended (the provider defaults of `profile-defaults.ts`), To download with its size and the download's progress, and All of X's models (the service's whole list, `ModelPicker`). A service without its key asks for it inside the row (`KeyField`): the job keeps its old service until the key works, then takes the new one, and the row offers the service for the other jobs it can do. Local models download from the row and are used once they're there (Whisper from `download_model`, Parakeet from `meeting_model_download`). Thinks and answers adds Claude's effort and Ollama's thinking; Speaks the voice for each language, with Try and Piper's install; Gemini Live, picked in Listens, merges it with Speaks into Listens and speaks, with its model, and Speaks hides. Remembers is always the brain (one brain for memory). Searches the web has Claude's own search (with Claude) and Tavily's key; Keys lists every service's key, each opening its field. Listens opens with Yoru listens as a switch, Speaks with Yoru answers aloud, and Speaks (or Listens and speaks, with Gemini Live) ends with the conversation's follow-ups. Transcribes ends with the meeting's own choices: noticing a call, the kind of transcript, Detailed or Simple, each a card with a short example (since 2026-11-24, docs/meetings.md; a transcriber that doesn't time its lines makes it Simple), when to transcribe, the language and the speakers; Summarizes with the summary's style and whether to write it on its own. A meeting's "open settings" lands on Transcribes or Summarizes, and the status card's voice and meeting problems on their row. At the bottom of an open row, where the job's data goes. The provider wizard is no longer in Settings, only in the first run. What the board keeps itself is on its own page (since 2026-11-21). Pocket settings manage the recorder. The provider wizard (`profiles.ts`, `ui/Profiles.svelte`), used by the first run, has three steps: choose Google, OpenAI, Anthropic or Groq, save a key, then review and explicitly apply defaults. Google uses Gemini for chat, summaries, meeting audio and Live voice; OpenAI and Groq use their chat and speech recognition with local meeting transcription and local speech; Anthropic uses Claude and local speech and meeting transcription. The wizard lists missing downloads, offers to install local components, explains cloud data and the board's independent requirements. The board alone needs compatible cloud STT and TTS, not Gemini Live or the Mac's models; the existing board bridge may fall back to a saved Groq or OpenAI key for STT. Every model is chosen with the same picker (`ui/ModelPicker.svelte`, since 2026-11-20): it looks like the app's selects and opens a list with a search field, the described models first, and, since 2026-11-24, nothing else: every picker lists only models tried for its task (the brain's catalog models, every model Ollama has installed, the person's own choice, the speech services' described models), so no typed names and no service's whole list. This Mac holds the Mac's permissions, the notch and Yoru's MCP server in Claude Code; the board's page keeps what the board itself keeps: firmware, WiFi, then Hearing and sounds (the wake word, picked from the board's `wake_words` with `set_board_wake_word`, then listening for it, the chime, the volume with a test through the board, Yoru's sounds and the muted microphone), then How it behaves with the rest of its settings.

- The first run (`src/lib/Setup.svelte`, since 2026-11-18) has six steps: the language; the Mac's permissions (`ui/PermissionList.svelte`) with Yoru in the notch and noticing meetings (both on by default); the board; the setup; a first service; a few lines about you. The microphone is required: Next and Skip wait for it. The calendar and the system audio are for meetings and can be left for later. After the first run, `src/lib/PermissionGate.svelte` covers the window whenever the microphone isn't Yoru's (turned off in System Settings, a new Mac), and goes away by itself once it is: the list reads the permissions again every second. Settings → On the Mac lists them too, with Allow for one never asked (macOS adds Yoru to System Settings' list only once it has asked), Ask again for one turned down, and Change, which opens System Settings at it, to turn one off.
- `src/lib/updates.ts` and `bundled.ts`: the firmware the app carries and what flashing it changes, from `firmware/yoru/`.
- `src/Notch.svelte`: Yoru in the Mac's notch, the same bundle mounted in the notch's window (`window.__YORU_NOTCH__`, or `?notch` in the browser preview) ([notch.md](notch.md)).
- `src/lib/i18n/`: `en.ts` and `it.ts`, key for key (`npm run check` fails on a missing one).

## The Rust side

- `src-tauri/src/lib.rs`: the bridge to the board, voice, firmware, WiFi, the board's animation clips (`yoru_clips`, `yoru_play_clip`, `yoru_stop_clip`: raw JSON-RPC test hooks, not MCP tools), the MCP server's entry in Claude Code's config, timers, the tray.
- `src-tauri/src/notch.rs`: the notch's window above the menu bar, the pointer that lets clicks through, and the ⌥ Space push-to-talk key ([notch.md](notch.md)).
- `src-tauri/src/assistant.rs`: the assistant's commands (ask, inbox, tasks, memory, watchers, connectors) and the scheduler and connectors started with the app.
- `src-tauri/src/meetings.rs`: the meetings' commands (sources, start, stop, the recordings, import, transcripts one at a time, exports, the meetings' settings, the model's download) and the `meeting` event. The recording runs in `yoru-audio`, the Swift helper in `../audio/`, which `src-tauri/build.rs` builds into `src-tauri/binaries/` on every macOS build (it needs Xcode or its command line tools); `src-tauri/Info.plist` says why macOS asks for the microphone, the system audio, the calendar, the local network and Bluetooth.
- `src-tauri/src/pocket.rs`: the Pocket recorder's commands (status, sync, copy, delete, pair, forget, settings) and the `pocket` event (`docs/pocket.md`); each recording it brings is transcribed like an import.
- `src-tauri/Entitlements.plist`: the microphone (`com.apple.security.device.audio-input`) and calendar (`com.apple.security.personal-information.calendars`) entitlements, included in the signature through `tauri.conf.json`. Hardened Runtime stays enabled in release and local signed builds (`tools/build_app.sh`); without these entitlements macOS rejects the requests before showing a permission prompt. The usage descriptions in `Info.plist` and the user's consent are still required.
- `src-tauri/src/permissions.rs`: the Mac's permissions, read and asked by the app's own process (`permissions`, `request_permission`, `open_privacy`): the microphone with AVFoundation, the calendar with EventKit, the system audio with the TCC framework's own calls (looked up at run time; there's no public one). They used to be asked by `yoru-audio`, and macOS showed no prompt for a helper process, so the notch's "Allow" did nothing. A permission turned down, or one macOS neither grants nor asks about (a record left by an older build), is forgotten with `tccutil reset <service> it.bytebusters.yoru.hub` and asked again, so the button always brings macOS's prompt back: sending the user to System Settings instead led to a list Yoru wasn't on (an app shows up there only once a prompt was answered). System Settings opens only for a permission a profile holds, or one turned down again. The system audio reads as unsupported before macOS 14.2, where TCC doesn't know the service and says denied. The permissions at launch, the macOS version and each request are written in `yoru.log` (`[permissions]`).

npm run dev           # the UI in a browser, mocked
npm run tauri dev     # the real app
npm run check         # svelte-check
npm run build         # the UI bundle
